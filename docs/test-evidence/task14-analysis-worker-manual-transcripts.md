# 分析任务与人工转写验证

日期：2026-08-24

## 本次实现

- 咨询完成事件由分析任务进程分批读取。每批最多 20 条，同一条消息只有取得租约的进程可以处理。
- 租约到期后，其他进程可以接手。任务取消不会增加失败次数，也不会把消息误标成已处理。
- 同一咨询即使出现两条完成事件，也只会建立一个分析任务；两个进程同时请求时也不会收到唯一键错误。
- 没有人工转写时，任务进入 `NeedsManual`，原因是 `TRANSCRIPT_REQUIRED`。
- 临时失败后分别等待 10 秒和 30 秒再试。第三次失败停止自动重试，任务进入 `NeedsManual`，保留失败码供人工查看。
- `POST /api/v1/consultations/{id}/transcript` 只允许咨询本人或本次咨询师提交，而且必须等咨询结束。
- 第一版来源必须是 `ManualUpload`，后续版本必须是 `ManualCorrection`。校对会新增版本，不会覆盖旧稿。
- 每一版保存咨询编号、版本号、来源、正文、SHA-256 和创建时间。分析任务指向确切版本。
- 人工转写 Provider 可以读取指定版本；没有指定版本时读取最新版本。当前不接云端转写服务。
- `scripts/Run-AnalysisWorker.ps1` 从本机 `.env` 读取数据库密码，只传给当前进程，不写入用户或系统环境变量。
