# 真人文字咨询验证

日期：2026-08-22

## 本次实现

- `/hubs/chat` 提供加入咨询和发送消息两个方法。只有患者本人和本次咨询的咨询师可以加入。
- 消息先写入 PostgreSQL，再通过 SignalR 广播。同一 `clientMessageId` 重试时返回原消息，不重复广播，也不重复写入。
- 历史接口支持 `afterSequence`，手机端和管理端断线重连后只补回缺少的消息，并按消息编号去重、按顺序号排列。
- Redis 记录每个咨询里的在线连接。咨询师上线和离线时，手机端可以收到状态变化。
- 手机端可从已确认的真人文字订单进入咨询。管理端可输入咨询编号进入同一咨询并发送消息。
- 管理端或客户端切换咨询编号时，先断开旧连接并清空旧消息，避免把两次咨询混在一起。
- 消息正文只保存在 `messages` 表和返回给咨询双方；应用日志不记录正文。

## 失败用例

- 后端测试开始时，`/hubs/chat/negotiate` 返回 404。
- 手机端和管理端测试开始时，咨询页面和连接代码尚不存在，测试不能编译或加载。
- Android 首轮联调在第二次输入时失败。原因是发送期间禁用了整个输入框，Android 原生输入连接被断开。调整为只锁发送按钮、发送前清空本轮内容后，连续发送恢复正常。
- 代码审查补充了切换咨询用例。修复前两端都没有停止旧连接，测试得到的停止次数为 0；修复后旧连接会先关闭，旧消息不会带到新咨询。
