# 规则型 AI 与危机安全门验证

日期：2026-08-22

## 本次实现

- `POST /api/v1/consultations/{id}/ai-turns` 只允许咨询本人在进行中的 AI 文字咨询中调用。真人咨询、视频咨询和其他用户都会被拒绝。
- 用户消息先保存，再判断最近 8 条用户消息。系统不把 AI 自己的回复送回危机规则，避免安全提示里的词再次触发规则。
- 强危机规则先运行。行为正在发生，或同时出现意图、计划或工具、时间时，固定返回 12356、120 和 110 的安全提示，不再生成普通回复。
- “没有”“并不”“不会”“从未”等否定词会在命中词前的短窗口内取消该次命中；新闻、电影、量表题目和转述他人的语句不会当成本人的危机表达。转述状态可以跨逗号延续，出现“但我”“可是我”等明确转回本人后重新判断。
- 非危机消息按冻结的本机规则返回简短追问。例如“最近很难过”返回“这几天不好过。哪件事最让你难受？”。
- 同一请求重复发送时复用原来的用户消息和 AI 回复。旧消息重试只读取该消息及之前的记录，不会被后来的危机消息改判。
- 危机回复和 `EscalationRequested` 求助事件在同一次数据库提交中保存。事件只含咨询编号、用户编号和规则编号，不保存消息正文。
- 本机通知发送器只记录一份可重试回执，不接入短信或推送。通知通道失败时，危机回复和已落库的求助事件仍然保留，用户端不会因此收不到安全提示。
- 应用日志只记录消息编号和长度，不记录用户正文、规则编号或危机判断。

## 规则文件

- `config/conversation-rules.v1.json`：普通倾听回复和兜底回复。
- `config/risk-rules.v1.json`：危机回复、最近消息数量、否定词、转述词和三组危机规则。
- 服务启动时检查规则版本和必填内容；版本不对、规则重复或分组为空时停止启动。

## 求助号码核对

- 中国政府网发布的国家卫生健康委 2025 年通知要求各地统一使用 `12356` 接通心理援助热线，并提供心理咨询、心理疏导和心理危机干预服务：<https://www.gov.cn/zhengce/zhengceku/202502/content_7003644.htm>
- 北京市通信管理局的常用紧急号码说明确认：`120` 是全国统一医疗急救电话，`110` 是公安报警求助电话：<https://bjca.miit.gov.cn/zwgk/tzgg/art/2022/art_8d4eb93ee3424f30826c97ee400e8937.html>

## 自动验证

- 危机规则专项单元测试：10 个通过，覆盖正在发生、意图加计划加时间、跨消息组合、否定、跨逗号转述、转回本人和最近 8 条边界。
- AI 安全集成测试：8 个通过，覆盖普通回复、危机固定回复、否定与转述、重复请求、求助事件、通知去重、旧消息重试、真人咨询拒绝和越权拒绝。
- 规则回复 Provider 和本机通知 Provider 合同测试：7 个通过。
- 全仓单元测试：84 个通过。
- 全仓合同测试：83 个通过。
- 全仓集成测试：59 个通过。
- .NET 格式检查通过；EF 模型没有待生成的迁移；NuGet 未发现已知漏洞。

所有用例只使用合成中文短句和虚构账户，没有真实患者资料。当前规则用于演示安全分流，不是医学诊断，也不计算精神状态分数。60 个合成案例的完整评分门禁安排在 Task 20；Android 2D 虚拟人、离线语音和危机页面安排在 Task 13。
